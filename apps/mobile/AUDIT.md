# Tigrinya iOS audit and implementation plan

The first mobile target bundles the existing standalone learning experience. It is an independent Capacitor package under `apps/mobile`; the Next.js application, its lockfile and its ASP.NET Core and PostgreSQL services remain unchanged. This is a development preview, not an approved release.

## Starting point and scope

The standalone HTML, CSS and JavaScript implementation is the best initial slice. It contains the complete current 293-form Fidäl catalogue, visual lessons and checks, freehand writing and text entry, Unit 2's picture-word lessons and review path, twenty games, twenty complete Stories, and optional pronunciation cards. The shared Neri bear, review records and dictionary attribution travel with the activities. Existing code handles unavailable recordings, missing stroke data, empty saved practice and incorrect attempts.

These are working interactive features rather than a remote website landing page. They offer a credible starting point for an original educational app. That is a product assessment, not a prediction of Apple approval. The material remains pending qualified Tigrinya review; approved native pronunciation recordings and reviewed teacher stroke data are missing. The English instructions, cultural suitability, accessibility and independently usable child experience still require review and real-device observation. The project has no repository-wide software licence granting distribution rights. Existing dictionary attribution and media licences must be retained and checked before distribution.

Apple's [minimum functionality guidance](https://developer.apple.com/app-store/review/guidelines/#minimum-functionality) requires useful app functionality beyond a repackaged website. Offline interactive learning and private recording are meaningful capabilities; packaging alone does not establish compliance. No App Store name, description, age rating, privacy policy, screenshots or signing team is assumed.

## Why the complete Next app is not exported

| Area            | Current implementation                                                                                                                                                                                                       | Mobile approach                                                                                                                                                                                                                                                                                                                                                                  |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Output          | `apps/web/next.config.ts` uses `output: "standalone"`; its output includes a Node.js server.                                                                                                                                 | Bundle local HTML/assets in `apps/mobile/www`. Do not change web output.                                                                                                                                                                                                                                                                                                         |
| Dynamic lessons | `app/learn/[id]/page.tsx` awaits request route params and has no `generateStaticParams()`. Published IDs are not a fixed build-time corpus.                                                                                  | First slice uses the existing local lesson routes. A later account/course client should resolve a validated ID from a client route such as `lesson.html?id=...`, fetch the published snapshot and handle authentication/errors; alternatively pre-render only a known published inventory with an explicit update policy. Do not export unknown IDs or invent lessons.           |
| Server headers  | Next emits referrer, permissions, frame and MIME headers.                                                                                                                                                                    | These HTTP headers are not bundled files. The mobile shell adds a restrictive CSP and referrer metadata; native WebView navigation restrictions and iOS ATS handle additional boundaries. CSP cannot reproduce every HTTP header. API security remains on the server.                                                                                                            |
| Authentication  | MSAL Browser uses a web SPA registration, `window.location.origin + /signin`, and in-memory tokens.                                                                                                                          | Account-free first slice. Do not embed the browser sign-in UI or copy its redirect assumptions. A later native client needs a separate Entra public-client registration, system authentication session/MSAL iOS, PKCE, an owner-supplied callback scheme and Keychain token storage. The API must validate the intended audience/scope/issuer. Never add a client secret to iOS. |
| API URL         | Web defaults to `http://127.0.0.1:5080`. On an iPhone that is the phone itself.                                                                                                                                              | Offline by default. Non-offline builds require an explicitly supplied HTTPS API origin; production additionally requires explicit acknowledgement. There is no database connection string or web fallback. The only initial API action is a user-initiated, read-only `/health/live` check.                                                                                      |
| CORS            | Production API currently filters allowed origins to HTTPS origins; `capacitor://localhost` would be discarded.                                                                                                               | Do not loosen web CORS. Use Capacitor's native HTTP transport for the explicit health check. Browser preview requests still require exact server CORS permission. A future WebView-fetch client requires a deliberately reviewed native-origin policy, not `*`. Native HTTP does not bypass server authentication.                                                               |
| Microphone      | Pronunciation cards optionally use `getUserMedia` and `MediaRecorder`, negotiate MP4/WebM/Ogg, cap clips at eight seconds and discard them on leave. Secure-context/permission failures already fall back to speaking aloud. | Keep that browser flow unchanged. Add a small mobile-only private recording page using AVAudioRecorder through a local Capacitor plugin, an accurate usage description, bounded temporary files and deletion on cancel/background/leave. No uploading, saving or grading. Unsupported browser recording stays optional.                                                          |
| Offline         | Next has a production-only service worker with partial caching; authenticated progress has no offline outbox.                                                                                                                | Bundle the selected activities locally; do not install the web service worker or imply offline account sync. Existing opt-in device practice saving stays separate.                                                                                                                                                                                                              |

No other Next blockers are assumed: the audit found no web Server Actions, request-bound Next API handlers, cookie-based server auth or `next/image` usage requiring migration in this slice. Client-side service calls are not in themselves static-export blockers. The exact limitations are documented in the [Next static-export guide](https://nextjs.org/docs/app/guides/static-exports).

## Safe implementation sequence

1. Snapshot existing tracked files, including uncommitted bear work, before editing. Keep all new runtime/build/test/native files under `apps/mobile`, with a separate npm lockfile outside the root workspaces.
2. Pin matching Capacitor 8.6.2 core, CLI and iOS packages. Its CLI supports Node 22+, compatible with this repository's Node 24. [Capacitor 8 iOS](https://capacitorjs.com/docs/ios) supports iOS 15+ and requires Xcode 26+; this Mac has Xcode 26.3.
3. Copy an explicit runtime inventory from source without executing or rewriting the web builders. Preserve the bytes of content/scripts; add mobile navigation, safe-area styles and policy metadata only to the generated HTML copies.
4. Build the offline shell and validate every local asset/link and source hash. Configuration must reject loopback, credentials, HTTP and implicit production access. Configuration values shipped in the app are public, never secrets.
5. Add an iOS project with conspicuous placeholder identity and no development team. CLI native builds disable signing and never provision devices. Add only the microphone permission used by the private recording feature. Keep native HTTP read-only and opt-in.
6. Exercise the bundled lesson flow, writing, review, Stories, games, native-recording success/cancel/failure adapters, configuration failures and mobile layouts. Run an unsigned simulator build where tooling permits, then verify the existing web checks/build and source preservation.

## Release gates and owner input

Supply the actual bundle identifier, display name, signing team, approved app icons, an explicitly chosen HTTPS staging/production API origin if needed, and native auth registration only when accounts are added. Review licences, child privacy disclosures and all language/media content. This slice intentionally leaves account functionality unavailable and production networking disabled by default. A release check must not pass while placeholder identity/icons and pending content remain. No database, deployment, Git commit, push or Apple submission is part of this work.

Native account design should follow Microsoft's [iOS sign-in setup](https://learn.microsoft.com/en-us/entra/identity-platform/quickstart-mobile-app-ios-sign-in) and [MSAL redirect URI requirements](https://learn.microsoft.com/en-us/entra/msal/objc/redirect-uris-ios). Those requirements depend on the actual tenant, bundle ID and chosen authentication approach; no sample registration or redirect URI is adopted here.
