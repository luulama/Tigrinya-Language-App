# Contributing

Keep domain invariants in the domain layer, orchestration and validation in application features, storage/cloud adapters in infrastructure, and HTTP concerns at the API boundary. A frontend permission check improves usability but cannot replace server authorisation. Prefer a focused vertical slice to a new abstraction or microservice.

Preserve the original standalone app and its sourced dictionary, review records and licence attribution. New curriculum content must include real sources and review status. Never add invented Tigrinya sentences, fabricated reviewer credentials, automatically approved generated media or a synthetic substitute for missing native recordings.

Run the engineering checks in DEVELOPMENT.md and the original check_all suite before proposing a change. Add regression coverage for a defect rather than mirroring implementation details. Keep migrations and package locks in source, review generated SQL, and use explicit algorithm/content versions for evidence changes. Keep secrets, private recordings, learner submissions and SDK/tool caches out of commits.

All new code must compile. Format TypeScript/TSX with the checked-in Prettier tool and C# with dotnet format. Keep public DTOs free of answer keys and private author/reviewer data. Changes that add external data collection, cloud accounts, publication or spending require explicit scope; they are not incidental consequences of a UI improvement.
